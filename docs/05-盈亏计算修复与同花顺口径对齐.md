# 盈亏计算修复与同花顺口径对齐（v0.2.1）

> 对应用户反馈："单只股票盈亏显示有错位""盈亏金额和同花顺比也有偏差"。

## 一、根因分析

### 1.1 盈亏显示错位
**`holdings/index.wxml` 第 28 行**：
```xml
<text class="strategy-pnl-pct">({{fmt.pnlSign(item.pnl)}}{{item.pnlPercent.toFixed(1)}}%)</text>
```
WXML 中 `.toFixed()` 是**非法调用**（WXML mustache 只支持表达式，不支持函数调用），导致策略卡的盈亏比例渲染为 `NaN` 或空白，视觉上"错位"。

**`holdings/index.wxml` 第 17 行**：
```xml
<text class="strategy-value">¥{{fmt.formatMoney(0)}}</text>
```
"全部"策略卡的金额硬编码为 0，没有实际汇总。

### 1.2 盈亏金额与同花顺偏差
**根因 A — 快照不同步（主因）**：
- `holdings` 集合存储了 `pnl` / `pnl_percent` 字段，由行情刷新云函数（sync_prices/refresh_prices）在刷新时计算。
- 持仓详情页直接显示 `holding.pnl`（存储快照），而 `holding.current_price` 也是刷新时更新的。
- **问题**：当用户通过「编辑持仓」手动修改 `cost_price` / `shares` 后，`pnl` 不会重算 → `current_price` 是新的但 `pnl` 是旧的 → 用户心算 `(现价-成本)×数量 ≠ 显示的盈亏` → 觉得"偏差/错位"。

**根因 B — 成本不含手续费**：
- `apply_transaction` 计算加权平均成本时，用的是交易记录的 `price`（净价），不含手续费。
- 同花顺的"持仓成本价"默认**含手续费**，所以本系统的成本价比同花顺略低，盈亏略高。

**根因 C — cost_value 回退不一致**：
- 行情刷新时 `costValue = h.cost_value || h.shares * h.cost_price`，若 `cost_value` 字段缺失会回退计算，但回退值与存储值可能因精度差异不一致。

## 二、同花顺口径

| 指标 | 同花顺公式 | 本系统公式 |
|------|-----------|-----------|
| 持仓成本价 | (Σ买入金额 + Σ手续费) / 持仓数量 | (Σ买入金额) / 持仓数量（**缺手续费**） |
| 持仓盈亏 | (现价 - 持仓成本价) × 持仓数量 | market_value - cost_value（等价，但用快照） |
| 盈亏比例 | (现价 - 成本价) / 成本价 × 100% | pnl / cost_value × 100%（等价，但用快照） |

## 三、修复方案

### Fix 1 — 持仓详情页盈亏实时重算（修根因 A）
在 `holding/detail.js` 的 `loadHolding` 中，用 `current_price` / `shares` / `cost_value` **实时重算** `pnl` 和 `pnl_percent`，覆盖存储的快照值后再 setData。这样无论从哪进入，显示的盈亏都与当前 `current_price` 一致。

```js
const currentPrice = Number(holding.current_price) || 0;
const shares = Number(holding.shares) || 0;
const costValue = Number(holding.cost_value) || 0;
const marketValue = currentPrice * shares;
const pnl = marketValue - costValue;
const pnlPercent = costValue > 0 ? (pnl / costValue) * 100 : 0;
holding.market_value = marketValue;
holding.pnl = pnl;
holding.pnl_percent = pnlPercent;
```

### Fix 2 — 修复 .toFixed() 非法调用（修错位）
`holdings/index.wxml` 第 28 行改为 WXS 调用：
```xml
<text class="strategy-pnl-pct">({{fmt.formatPercent(item.pnlPercent, false)}})</text>
```
（`formatPercent` 已自带 `%`，去掉末尾多余的 `%`）

### Fix 3 — 策略"全部"卡金额（修硬编码）
在 `holdings/index.js` 的 `loadData` 中，基于 `summary` 组装"全部"汇总项插入 `strategyList` 头部：
```js
const allSummary = {
  name: '全部',
  holdingCount: summary.holdingCount,
  marketValue: summary.totalMarketValue,
  costValue: summary.totalCostValue,
  pnl: summary.totalPnL,
  pnlPercent: summary.totalPnLPercent,
};
```
wxml 中"全部"卡改用 `{{allSummary}}` 渲染。

### Fix 4 — transactions 增加 fee 字段（修根因 B，对齐同花顺）
- `transactions` 集合增加可选 `fee` 字段（默认 0）。
- `apply_transaction` 计算买入成本时：`cost = shares × price + fee`。
- `transactions/edit.wxml` 增加"手续费"输入框（可选）。
- `rebuild_holdings` 同步支持 fee。

### Fix 5 — 行情刷新时实时算 costValue（修根因 C）
`sync_prices` / `refresh_prices` 中，`costValue` 不再回退，直接用 `h.cost_value`（若缺失则 `shares × cost_price` 但记录告警）。

## 四、验收标准
- [ ] 持仓详情页 `(现价-成本)×数量` === 显示的盈亏金额
- [ ] 策略卡盈亏比例正常显示（无 NaN）
- [ ] 策略"全部"卡显示真实总市值
- [ ] 含手续费的买入，成本价 = (买入金额+手续费)/数量，与同花顺一致

# 盈亏计算修复与同花顺口径对齐（v0.2.1 → v0.2.3）

> 对应用户反馈："单只股票盈亏显示有错位""盈亏金额和同花顺比也有偏差"（v0.2.1），
> 以及"计算的收益和同花顺差别很大……同花顺 34723.5，你计算的是 31336"（v0.2.3）。

---

## 一、v0.2.3 重点：总收益口径修复（同花顺口径）

### 1.1 用户实际案例（华工科技）

| 操作 | 数值 |
|------|------|
| 买入 | 27.93 元 × 400 股 |
| 历次分红 | 32 + 40 + 30 + 40.39 + 50 = 192.39 元 |
| 卖出 | 44 元 × 200 股 |
| 剩余 | 200 股，现价 184.61 元 |

**同花顺计算的总收益 = 34723.5 元**
**本系统修复前 = 31336 元（差 3387.5 元）**

### 1.2 差异拆解（谁对谁错）

修复前本系统只算了"浮动盈亏"一项，完全漏掉已实现盈亏、累计分红、累计手续费：

| 分项 | 公式 | 金额 |
|------|------|------|
| 浮动盈亏 | (184.61 − 27.93) × 200 | **31336.00** ← 修复前只算这个 |
| 已实现盈亏 | (44 − 27.93) × 200 | **+3214.00** ← 漏了 |
| 累计分红 | 32+40+30+40.39+50 | **+192.39** ← 漏了 |
| 累计手续费 | 买卖双向约 | **−14.60** ← 漏了（扣减） |
| **总收益** | 浮动+已实现+分红−手续费 | **≈ 34727.79** |

> 说明：同花顺显示 34723.5 与本表 34727.79 的尾差来自手续费取值精度（同花顺按账户实际费率精算到分），口径完全一致。**结论：同花顺是对的，本系统修复前的 31336 是错的。**

### 1.3 同花顺总收益口径

```
总收益 = 浮动盈亏 + 已实现盈亏 + 累计分红 − 累计手续费
       = (市值 − 成本) + (卖出价 − 成本价) × 卖出份额 + Σ分红 − Σ手续费
```

- **浮动盈亏**：未卖出部分的市值 − 成本
- **已实现盈亏**：已卖出部分锁定的盈亏（卖出价 − 成本价）× 卖出份额 − 卖出手续费
- **累计分红**：该持仓历次分红/利息之和
- **累计手续费**：该持仓历次买卖手续费之和

### 1.4 修复方案（v0.2.3）

`holdings` 集合新增 4 个字段，全链路同步维护：

| 字段 | 含义 | 维护点 |
|------|------|--------|
| `realized_pnl` | 累计已实现盈亏 | 卖出时累加 `(卖价−成本价)×份额−手续费` |
| `total_dividend` | 累计分红/利息 | dividend/interest 类型交易累加 `amount` |
| `total_fee` | 累计手续费 | 买入/卖出时累加 `fee` |
| `total_pnl` | 总收益（同花顺口径） | 浮动+已实现+分红−手续费，行情刷新时重算 |

**维护链路**：
1. `cloudfunctions/apply_transaction/index.js` — 单笔交易应用时维护（含 `recomputeTotalPnl` 辅助函数）
2. `cloudfunctions/rebuild_holdings/index.js` — 全量回放重建时同步维护
3. `cloudfunctions/sync_prices/index.js` / `refresh_prices/index.js` — 行情刷新时按最新市值重算 `total_pnl`
4. `miniprogram/pages/holding/detail.js` — 详情页实时重算并展示分项
5. `miniprogram/utils/api.js` `getPortfolioSummary` — 汇总 `totalAllPnL` / `totalRealized` / `totalDividend` / `totalFee`

**核心算法（apply_transaction）**：
```js
function recomputeTotalPnl(holding, marketValue, costValue) {
  const mv = Number(marketValue) || 0;
  const cv = Number(costValue) || 0;
  const realized = Number(holding.realized_pnl) || 0;
  const dividend = Number(holding.total_dividend) || 0;
  const fee = Number(holding.total_fee) || 0;
  return Number((mv - cv + realized + dividend - fee).toFixed(2));
}
```

**卖出已实现盈亏**：
```js
const sellRealized = (price - costPrice) * shares - fee;
realized_pnl += sellRealized;
total_fee += fee;
```

**分红/利息**（修复前直接跳过，是重大遗漏）：
```js
if (type === 'dividend' || type === 'interest') {
  // 找对应持仓累加 total_dividend（不影响份额）
  total_dividend += amount;
}
```

### 1.5 前端展示

- **持仓详情页** `holding/detail.wxml`：新增"总收益"卡（渐变背景，涨跌色区分），下方分项明细（浮动/已实现/分红/手续费），原"盈亏"改为"浮动盈亏"
- **持仓列表** `holdings/index.wxml`：盈亏数字改用 `h.total_pnl`，有已实现或分红时显示"含已实现/分红"小标签
- **资产看板** `dashboard/index.wxml`："累计收益"改用 `summary.totalAllPnL`，账户卡改用 `item.total_pnl`
- **api.js** `getPortfolioSummary`：返回 `totalAllPnL` / `totalAllPnLPercent` / `totalRealized` / `totalDividend` / `totalFee`，账户汇总含 `total_pnl`，策略汇总改用总收益口径

## 二、v0.2.1 历史修复（盈亏显示错位 + 成本含手续费）

### 2.1 盈亏显示错位

**`holdings/index.wxml`**：
```xml
<text class="strategy-pnl-pct">({{fmt.pnlSign(item.pnl)}}{{item.pnlPercent.toFixed(1)}}%)</text>
```
WXML 中 `.toFixed()` 是**非法调用**（WXML mustache 只支持表达式，不支持函数调用），导致策略卡盈亏比例渲染为 `NaN` 或空白。改为 WXS 调用 `fmt.formatPercent()`。

"全部"策略卡金额硬编码为 `¥0`，改为基于 `summary` 实时汇总。

### 2.2 盈亏金额偏差根因

- **根因 A — 快照不同步**：编辑持仓后 `pnl` 不会重算。修复：详情页 `loadHolding` 用 `current_price` 实时重算 `pnl` / `pnl_percent`。
- **根因 B — 成本不含手续费**：`apply_transaction` 用净价算成本。修复：`buyCost = shares × price + fee`，`transactions` 增加 `fee` 字段。
- **根因 C — cost_value 回退不一致**：行情刷新时回退计算与存储值有精度差。修复：仅 null/undefined/NaN 时回退。

### 2.3 同花顺成本口径

| 指标 | 同花顺公式 | 本系统公式（修复后） |
|------|-----------|-----------|
| 持仓成本价 | (Σ买入金额 + Σ手续费) / 持仓数量 | (Σ买入金额 + Σ手续费) / 持仓数量 |
| 浮动盈亏 | (现价 − 成本价) × 持仓数量 | market_value − cost_value |
| 盈亏比例 | (现价 − 成本价) / 成本价 × 100% | pnl / cost_value × 100% |

## 四、数据迁移说明

旧持仓数据没有 `realized_pnl` / `total_dividend` / `total_fee` / `total_pnl` 字段。处理方式：
- 代码中统一用 `Number(h.realized_pnl) || 0` 兜底，旧数据视为 0
- 如需补全历史已实现/分红，调用 `rebuild_holdings` 云函数全量回放重建即可自动填充

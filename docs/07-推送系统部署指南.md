# 推送系统部署指南（07）

> 本文档说明「个人资产管家」推送通知系统的部署步骤：订阅消息模板申请、模板 ID 替换、云函数部署、定时触发器部署、云环境 env 配置。
>
> 推送系统由以下三组能力组成：
> - 早报 / 晚报资讯推送（`push_news`）
> - 推送设置云端持久化（`save_notify_settings` / `get_notify_settings`）
> - 涨跌提醒（`check_price_alert`）

---

## 一、订阅消息模板申请步骤

推送依赖微信「订阅消息」。每个推送场景需要单独申请一个模板，每个模板有唯一的 `templateId`。

1. 登录 [微信公众平台](https://mp.weixin.qq.com/)（使用小程序账号）。
2. 左侧菜单 → 「功能」→「订阅消息」。
3. 在「我的模板」中点击「添加」→「公共模板库」或「我的模板库」。
4. 按下表选择/申请 3 个模板，并记录每个模板的 **模板 ID** 和 **字段名称**（如 `thing1`、`time3` 等，不同模板字段名可能不同）。

| 推送场景 | 用途 | 建议字段（示例） |
| --- | --- | --- |
| 早报 | `morningNews` 开启时，每日 08:00 推送要闻 | 标题 `thing`、摘要 `thing`、时间 `time` |
| 晚报 | `eveningNews` 开启时，每日 17:00 推送收盘速览 | 标题 `thing`、摘要 `thing`、时间 `time` |
| 涨跌提醒 | `priceAlert` 开启时，持仓涨跌幅超阈值时推送 | 产品名 `thing`、涨跌幅 `amount/character_string`、时间 `time` |

5. 申请到模板后，把模板 ID 填入代码（替换占位符，见第二节）。
6. **注意**：模板字段名（`thing1`/`amount2`/`time3` 等）必须与申请到的真实模板字段一致，否则 `cloud.openapi.subscribeMessage.send` 会报字段不匹配错误。代码中的字段名同样是占位实现，需按真实模板字段名调整。

> 微信订阅消息为「一次性订阅」：用户每次在小程序内点击「允许」授权一次，云函数可下发一条。`wx.requestSubscribeMessage` 即用于在小程序端向用户申请授权。当前模板 ID 为占位符，`requestSubscribeMessage` 调用必然 fail，属预期行为，不影响设置保存。

## 三、云函数部署步骤

需要部署的云函数（均位于 `cloudfunctions/` 目录下）：

| 云函数 | 作用 | 是否需定时触发器 |
| --- | --- | --- |
| `save_notify_settings` | 保存推送设置到 `notify_settings` 集合（按 openid） | 否 |
| `get_notify_settings` | 读取当前用户推送设置 | 否 |
| `push_news` | 早报/晚报资讯推送 | 是 |
| `check_price_alert` | 涨跌提醒 | 是 |

### 3.1 在微信开发者工具中部署
1. 打开微信开发者工具，加载本项目。
2. 确认 `project.config.json` 中 `cloudfunctionRoot` 指向 `cloudfunctions/`。
3. 在左侧资源管理器，右键每个云函数文件夹 → 「上传并部署：云端安装依赖」。
   - 依赖 `wx-server-sdk` 会在云端自动安装。
4. 对 `push_news` / `check_price_alert`，部署后还需单独创建定时触发器（见第四节）。

### 3.2 创建 `notify_settings` 集合
推送设置依赖云数据库 `notify_settings` 集合。请二选一：
- 方式 A（推荐）：在云开发控制台 → 数据库 → 「+」新建集合 `notify_settings`。
- 方式 B：直接在小程序「推送设置」页保存一次设置，`save_notify_settings` 首次 `add` 时云数据库会自动创建集合。

建议为 `notify_settings._openid` 建立索引以加速按 openid 查询。

### 3.3 安全规则
`notify_settings` 集合建议设置安全规则：仅允许用户读写自己的记录（`doc._openid == auth.openid`）。云函数以 admin 权限运行，不受安全规则限制，可读写全部记录（`push_news` / `check_price_alert` 需要遍历全部用户）。

## 四、定时触发器部署

定时触发器写在各云函数的 `config.json` 的 `triggers` 字段中，**部署云函数时不会自动创建触发器**，需在云开发控制台手动确认/创建。

### 4.1 push_news（早报 / 晚报）
文件：`cloudfunctions/push_news/config.json`

```json
"triggers": [
  { "name": "morningNews",  "type": "timer", "config": "0 8 * * *" },
  { "name": "eveningNews",  "type": "timer", "config": "0 17 * * *" }
]
```
- 早报：每天 08:00（cron `0 8 * * *`）
- 晚报：每天 17:00（cron `0 17 * * *`）
- `push_news` 通过定时事件的 `TriggerName`（`morningNews` / `eveningNews`）区分早报/晚报并选择对应模板与开关字段。

### 4.2 check_price_alert（涨跌提醒）
文件：`cloudfunctions/check_price_alert/config.json`

```json
"triggers": [
  { "name": "priceAlertTrigger", "type": "timer", "config": "50 14 * * 1-5" }
]
```
- 交易日（周一至周五）14:50 收盘前触发（cron `50 14 * * 1-5`）。

### 4.3 在控制台创建/确认触发器
1. 云开发控制台 → 云函数 → 选中对应云函数 → 「触发器」标签。
2. 若部署时未自动创建，点击「创建触发器」，按上述 `name` / `config` 填入。
3. cron 表达式为标准 5 段：`分 时 日 月 周`，时区为 UTC+8（北京时间）。

> 提示：`fetch_news`（资讯抓取）同样配置了 `0 8 * * *` / `0 17 * * *` 触发器，会在推送前刷新 `news_cache`。建议确认 `fetch_news` 触发器已启用，保证推送时有最新资讯。

## 五、云环境 env 配置

各云函数 `config.json` 中的 `"env"` 字段当前为占位值 `"your-env-id"`，**部署前需替换为真实云环境 ID**。

涉及文件（共 4 个新建/修改的 config.json）：
- `cloudfunctions/save_notify_settings/config.json`
- `cloudfunctions/get_notify_settings/config.json`
- `cloudfunctions/push_news/config.json`
- `cloudfunctions/check_price_alert/config.json`

获取真实 env ID：
1. 微信开发者工具 → 工具栏「云开发」→ 打开云开发控制台。
2. 顶部环境名称旁即为环境 ID（形如 `cloud1-2g5abc...`）。
3. 用真实环境 ID 替换上述 4 个文件中的 `"your-env-id"`。

> 说明：云函数体内已使用 `cloud.init({ env: cloud.DYNAMIC_CURRENT_ENV })`，运行时会自动取当前部署环境，无需在代码中硬编码 env。`config.json` 中的 `env` 字段用于开发者工具部署时的环境选择，替换为真实 ID 可避免部署到错误环境。

## 七、常见问题

1. **保存设置后 `requestSubscribeMessage` 报错**：模板 ID 为占位符时必然 fail，属预期；替换真实模板 ID 后即可正常弹出授权。
2. **`push_news` 返回 `success:false, error:"..."`**：查看 `errors` 数组定位失败原因（常见：模板未配置、用户未授权、字段名不匹配）。
3. **定时触发器不执行**：确认控制台触发器已创建且 cron 时区为北京时间；`push_news` 通过 `event.TriggerName` 区分早/晚报。
4. **`check_price_alert` 未推送**：确认用户 `notify_settings.priceAlert === true` 且持仓 `daily_change` 或 `prev_close` 字段存在且涨跌幅超过阈值。

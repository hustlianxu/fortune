# 需求分析与设计原则（v0.2.0）

## 一、用户原始诉求

> 目前看起来这个小程序花里胡哨，色块分布也是让人大跌眼镜……简单易用，且对于某一只个股可以进行买卖操作的记录（可选），最好能从对应股票或者基金账户直接同步（可选）。界面希望清爽一些。

拆解为四个目标：

| # | 目标 | 优先级 | 性质 |
|---|------|--------|------|
| 1 | 界面清爽，消除"花里胡哨/色块混乱" | 高 | UI 重构 |
| 2 | 业务逻辑与代码优化，简单易用 | 高 | 架构 |
| 3 | 个股买卖记录（可选） | 中 | 功能增强 |
| 4 | 从股票/基金账户直接同步（可选） | 低 | 功能增强 |

## 二、现状诊断（"花里胡哨"的根因）

通过审计 `theme.wxss` 与各页面 `wxss`，定位到以下具体问题：

1. **多套渐变色互相打架**
   - dashboard 头部：`linear-gradient(135deg, #6c63ff → #4a42d6)`（紫）
   - AI 入口卡：`linear-gradient(135deg, #667eea → #764ba2)`（另一种紫）
   - 两个紫色渐变并存且色值不同，视觉割裂。
2. **Emoji 作为主视觉元素**：每个区块标题/入口都带大 emoji（🤖 📥 📒 🏦 等），信息密度低、风格不统一。
3. **硬编码颜色泛滥**：页面 wxss 里散落 `#6c63ff` `#8e8e93` `#f0f0f0` `#667eea` 等魔法值，未走 `theme.wxss` 的 CSS 变量，导致换肤/统一调色成本极高。
4. **交易色复用涨跌色，语义错乱**：`transactions` 里买入用 `--color-down`（绿）、卖出用 `--color-up`（红），与 A 股"涨红跌绿"惯例在语义上冲突，用户会误读。
5. **卡片阴影/圆角/间距不统一**：有的卡 `border-radius:20rpx`，有的 `24rpx`；阴影有的 `0.06` 有的 `0.12`。
6. **功能入口分散**：AI、导入、流水、账户管理分散在不同卡片，缺乏一致的信息层级。

## 三、设计原则（博采众长）

参考了蚂蚁财富、雪球、同花顺、Robinhood、Wise 等优秀金融/资产类产品的共性，提炼出本项目的四条原则：

### P1 — 克制用色（Color Restraint）
- **背景留白为主**，整屏大面积是浅灰底 + 白卡片，仅在关键数据（涨/跌/主操作）用色。
- **主色单一**：全局只有一个主色（见 `01-UI清爽化重构方案.md`），渐变仅在"总资产"这一个焦点卡使用，其余卡纯白。
- **涨跌色遵循 A 股惯例**：涨红跌绿，且**仅用于价格/盈亏数字**，不用于按钮/标签/交易类型。

### P2 — 清晰的视觉层级（Visual Hierarchy）
- 一屏只允许一个"英雄区"（Hero）：dashboard 顶部总资产卡。
- 其余卡片平铺、等权重，靠字号字重区分，而非靠色块。
- 列表项遵循「名称左 + 数值右」的对齐范式，数字右对齐便于扫读。

### P3 — 语义化配色（Semantic Tokens）
- 所有颜色经 CSS 变量声明，页面 wxss **禁止硬编码**十六进制值（允许 rgba 透明度叠加）。
- 交易类型用**中性灰阶 + 小色点**，不与涨跌色混淆。

### P4 — 简单易用（Simplicity）
- 核心路径 ≤ 2 跳：看资产 → 看持仓 → 记一笔交易。
- 可选功能（买卖记录、账户同步）做"渐进披露"：藏在持仓详情的次级入口，不占据首屏。

## 四、范围与非目标

**本版（v0.2.0）做：**
- 主题变量收敛 + 全局样式去硬编码
- dashboard / holdings / transactions / holding-detail / account-detail 五个核心页清爽化
- 持仓详情页新增"记一笔买卖"入口，写入 transactions 集合并反算持仓成本
- 提供从交易流水重建持仓的"账户同步"云函数（可选能力）

**本版不做（避免过度工程）：**
- 不接入券商 OpenAPI 实盘同步（合规与对接成本高，留作 v0.3 路线）
- 不重写 AI 分析模块（已稳定）
- 不新增暗色模式的完整适配（仅保留变量预留）

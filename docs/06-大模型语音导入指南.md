# 大模型语音导入交易流水指南（v0.2.1）

> 对应用户需求："历史持仓太杂了，操作又多，有没有办法快速录入……跟大模型语音输入之后让他自动帮我导入，或者我在外部把语音转换成文字之后让大模型自动帮我导入"。

## 一、使用场景

你有多笔历史交易要补录，手动逐条填写太繁琐。本功能允许你：
1. **方式 A（小程序内）**：在小程序「语音录入」页直接粘贴一段自然语言文字（外部语音转文字后粘贴，或直接打字），大模型自动解析成结构化交易，确认后批量导入。
2. **方式 B（外部 LLM）**：在任意 LLM 对话框（DeepSeek/ChatGPT/通义）里用本文档提供的提示词，把语音转文字喂给 LLM，拿到 JSON 后粘贴回小程序导入。

## 二、方式 A：小程序内语音录入

### 2.1 入口
「我的」→「批量导入持仓」旁新增「语音/文字录入交易」入口 → `pages/import/voice`

### 2.2 操作流程
1. 在文本框粘贴自然语言（支持多笔，一行一笔或自然段落均可）。
2. 选择目标账户（解析后的交易会挂到该账户；若文字中提到了账户名也可自动匹配）。
3. 点击「AI 解析」→ 调用 `parse_trades_by_text` 云函数，返回结构化交易数组。
4. 预览解析结果（可逐条编辑/删除/修正）。
5. 点击「确认导入」→ 批量写入 `transactions` 集合，并自动调用 `apply_transaction` 同步持仓。

### 2.3 支持的输入示例

```
3月15号买入1000股招商银行，36块5，手续费5块
4月20号卖出500股招商银行，38块2
5月10号买入2000股上证50ETF，2.85
6月1号分红500块
```

或自然段落：

```
我3月15号在36块5买了1000股招商银行，花了5块手续费。
后来4月20号38块2卖了500股。
5月10号又买了2000股上证50ETF，价格2块8毛5。
6月1号招行分红给了我500块。
```

## 三、方式 B：外部 LLM 手动解析

### 3.1 提示词模板（复制给任意 LLM）

```
你是一个金融交易记录解析助手。请把用户输入的自然语言交易描述解析成结构化 JSON。

规则：
1. 日期格式统一为 YYYY-MM-DD（年份缺失时用当前年份 2025）
2. 金额"36块5""36.5""36元5"都解析为 36.50
3. type 只能是：buy(买入) / sell(卖出) / dividend(分红) / transfer_in(转入) / transfer_out(转出) / fee(手续费) / interest(利息)
4. 产品代码缺失时填空字符串，产品名称尽量保留原文
5. 手续费：用户明确提到时填入 fee 字段（单位：元）；未提到则填 0（系统会按账户费率自动计算，无需估算）
6. 分红/利息类交易 shares 和 price 填 0，amount 填实际金额
7. buy/sell 的 amount = shares × price（不含手续费）
8. 只输出 JSON 数组，不要任何解释文字、不要 markdown 代码块标记

输出格式（严格遵循）：
[
  {
    "type": "buy",
    "product_name": "招商银行",
    "product_code": "",
    "shares": 1000,
    "price": 36.50,
    "fee": 5,
    "amount": 36500,
    "trade_date": "2025-03-15",
    "note": ""
  }
]

用户输入：
【在此粘贴你的语音转文字内容】
```

### 3.2 返回 JSON 结构约定

```typescript
interface ParsedTrade {
  type: 'buy' | 'sell' | 'dividend' | 'transfer_in' | 'transfer_out' | 'fee' | 'interest';
  product_name: string;   // 产品名称，如"招商银行"
  product_code: string;   // 产品代码，如"600036"；缺失填空串
  shares: number;         // 份额/数量；分红/利息填 0
  price: number;          // 单价；分红/利息填 0
  fee: number;            // 手续费（元）；无则填 0
  amount: number;         // 交易金额（元）；buy/sell=shares×price，dividend=分红金额
  trade_date: string;     // YYYY-MM-DD
  note: string;           // 备注，可空
}

// 云函数返回
interface ParseResult {
  success: boolean;
  trades: ParsedTrade[];
  warnings?: string[];    // 解析过程中的不确定项提示
}
```

### 3.3 拿到 JSON 后
- 粘贴到小程序「语音录入」页的「JSON 导入」tab，校验后批量导入。
- 或直接用 JSON 调用 `parse_trades_by_text` 云函数的 `mode: 'json'` 模式导入。

## 四、云函数 `parse_trades_by_text` 接口

### 4.1 入参
```js
{
  text: string,        // 自然语言文本（mode='text' 时必填）
  json: string,        // 已解析的 JSON 数组字符串（mode='json' 时必填）
  mode: 'text' | 'json',  // 默认 'text'
  account_id: string,  // 目标账户 ID
  provider: string,    // LLM 提供商，默认取用户已配置的第一个
  dry_run: boolean,    // true=仅解析不写入，false=解析并写入（默认 true）
}
```

### 4.2 返回
```js
{
  success: boolean,
  trades: ParsedTrade[],   // 解析结果
  warnings: string[],
  imported: number,        // dry_run=false 时实际写入条数
}
```

### 4.3 解析提示词（云函数内部使用）
云函数复用 `llm_gateway` 的 LLM 调用能力，使用上文 3.1 的提示词模板，temperature 设为 0 保证稳定输出。

## 四点五、手续费：可选 + 账户费率自动计算（v0.2.2 新增）

> 对应用户问题：「如果我帐户里面已经设置了各种手续费标准，那语音录入的时候还有必要说手续费吗？」

**结论：不用每次都说手续费。** 系统按以下优先级处理：

| 用户输入 | 处理方式 |
|---|---|
| 语音/文字明确提到手续费（如"花了5块手续费"） | 直接采用用户提供的值 |
| 未提到手续费（fee=0） | 调用 `utils/fee.js` 按目标账户的费率配置自动计算 |
| 账户未配置任何费率 | fee 保持为 0，与历史行为一致 |

### 4.5.1 自动计算口径（与同花顺一致）

**证券类（stock/etf/lof/hk_stock/us_stock）**

```
佣金 = max(成交金额 × 佣金率, 最低佣金)         // 沪市用 sh_*_rate，深市用 sz_*_rate
过户费 = 成交金额 × transfer_fee_rate           // 仅沪市，买卖双向
印花税 = 成交金额 × stamp_duty_rate             // 仅卖出

手续费 = 佣金 + 过户费(沪市) + 印花税(卖出)
```

**场外基金（fund_*）**

```
买入(申购) fee = max(金额 × subscription_fee_rate, subscription_fee_min)
卖出(赎回) fee = 金额 × redemption_fee_rate
```

### 4.5.2 product_type / exchange 的自动补全

为了让费率能正确匹配沪市/深市，云函数在解析后会自动补全：

1. **从已有持仓反查**：用 `product_code` 在该账户的 `holdings` 集合里查 `product_type`/`exchange`，命中则填入。
2. **代码前缀兜底推断**：
   - `60xxxx` / `68xxxx` / `51xxxx` / `50xxxx` → SH
   - `00xxxx` / `30xxxx` / `15xxxx` / `16xxxx` → SZ

### 4.5.3 透明可追溯

自动计算后会在 `warnings` 字段追加提示，预览页和导入完成提示都能看到，例如：

```
「招商银行」手续费由账户费率自动计算：¥5.12
「上证50ETF」手续费由账户费率自动计算：¥2.85
```

用户在预览页若觉得自动值不对，可手动编辑覆盖（手动录入页同款逻辑：手动改过就不再被自动覆盖）。

### 4.5.4 手动录入页同步支持

`pages/transactions/edit.js` 也接入了同一套费率计算器（`miniprogram/utils/fee.js`）：

- 选择账户、输入份额/单价后，手续费框留空时自动填充。
- 一旦用户手动修改手续费，标记为 `_feeTouched=true`，后续不再自动覆盖。
- 输入框下方有蓝色提示行：「按账户费率自动计算：¥X.XX（手动修改后将不再覆盖）」。

## 五、容错与确认机制
- **dry_run 默认 true**：先解析预览，不直接写入，避免误操作。
- **warnings 字段**：对不确定的解析（如产品名无法匹配代码、日期模糊）给出提示，用户在预览页可手动修正。
- **产品代码自动补全**：解析后调用 `lookup_product` 云函数按名称反查代码，匹配不到的留空让用户补。
- **重复检测**：导入前检查同 `account_id + product_code + trade_date + amount` 是否已存在，重复的标记跳过。

- [ ] dry_run 模式不写入数据
- [ ] 文档中的提示词可在任意 LLM 复用

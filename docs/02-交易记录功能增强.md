# 交易记录功能增强（v0.2.0）

> 对应需求目标 #3「对于某一只个股可以进行买卖操作的记录（可选）」。

## 一、现状

- 已有 `transactions` 集合与 `pages/transactions/*` 页面，支持独立的流水增删查。
- **缺口**：从持仓详情页无法直接"记一笔买卖"，且记账后**不会反算更新持仓**的份额/成本，流水与持仓是两套割裂的数据。

## 二、目标

让"记一笔买卖"成为持仓详情页的一等公民入口，且记账后自动同步持仓：

1. 持仓详情页新增「记一笔」按钮 → 跳转 `transactions/edit` 并预填产品/账户。
2. 交易保存后，自动 upsert 对应 `holdings` 记录：
   - 买入：累加份额，按加权平均法更新成本价。
   - 卖出：扣减份额，成本价不变；份额归零则标记为"已清仓"（保留记录，`shares=0`）。
   - 分红/利息：仅记录现金，不影响份额。
3. 持仓详情页展示该持仓的最近 N 笔交易。

## 三、数据模型

### 3.1 transactions（已有，无 schema 变更）
```
{
  _id, account_id, type, product_code, product_name,
  shares, price, amount, trade_date, note,
  created_at, updated_at
}
```

### 3.2 holdings（已有字段复用）
- `shares`：持仓份额
- `cost_price`：加权平均成本价
- `market_value`：市值（行情刷新时更新）
- 新增 `is_cleared`（bool）：是否已清仓，用于列表过滤。

## 四、加权平均成本算法

```
买入 N 股 @ P 元，原持仓 S 股 @ C 元：
  newShares = S + N
  newCost   = (S*C + N*P) / newShares

卖出 N 股：
  newShares = S - N   （不改变 cost_price）
  if newShares <= 0: is_cleared = true, shares = 0
```

## 五、实现位置

### 5.1 前端
- `pages/holding/detail.wxml`：顶部操作区加「记一笔买卖」按钮。
- `pages/holding/detail.js`：`onRecordTrade` 跳转 edit 页并带 `product_code`、`account_id`、`product_name` 预填参数；`onShow` 时刷新持仓 + 拉取最近交易。
- `pages/transactions/edit.js`：`onLoad` 读取 url 参数预填表单；保存成功后调用云函数 `apply_transaction` 反算持仓。

### 5.2 云函数 `apply_transaction`（新增）
入参：`{ transaction_id }` 或 `{ transaction_data }`
逻辑：
1. 读取该笔交易。
2. 查询 `holdings` 中 `account_id + product_code` 对应记录。
3. 按算法 upsert holdings。
4. 返回更新后的 holding。

幂等性：transaction 写入 `applied_holding`（bool）标记，已应用的重复调用直接跳过。

## 六、验收标准

- [ ] 持仓详情页有「记一笔」入口，预填产品/账户
- [ ] 买入后持仓份额与成本价正确更新
- [ ] 卖出后份额扣减，归零标记清仓
- [ ] 持仓详情页展示最近交易列表
- [ ] 重复应用同一笔交易不会重复累加（幂等）

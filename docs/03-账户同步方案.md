# 账户同步方案（v0.2.0 可选能力）

> 对应需求目标 #4「最好能从对应股票或者基金账户直接同步（可选）」。

## 一、定位

实盘券商 OpenAPI 同步涉及合规审核、签约、各家接口差异大，不适合在体验项目里硬接。
本版采用**"交易流水驱动"的轻量同步**：以 `transactions` 为单一事实源，从中重建/校准 `holdings`，达到"账户同步"的体验效果——用户只需记账，持仓自动跟上。

## 二、两种同步模式

### 模式 A：单笔同步（已由 `02-交易记录功能增强.md` 覆盖）
记账即同步，每笔交易保存时调用 `apply_transaction`。

### 模式 B：全量重建（本方案新增）
当用户历史数据与持仓不一致，或从外部导入了一批交易流水后，提供「一键重建持仓」入口，按 `trade_date` 升序回放所有交易，重算 holdings。

## 三、云函数 `rebuild_holdings`（新增）

入参：`{ account_id?, product_code? }`（不传则全量）
逻辑：
1. 查询范围内的全部 transactions，按 `trade_date asc, created_at asc` 排序。
2. 对每个 `(account_id, product_code)` 维护一个内存态 holding：
   - buy：累加份额 + 加权成本
   - sell：扣减份额
   - 其他：跳过份额
3. 回放完成后，upsert 到 `holdings` 集合（按 `account_id+product_code` 唯一）。
4. 清仓的标的写入 `shares=0, is_cleared=true`。
5. 返回统计：`{ rebuilt: N, cleared: M }`。

幂等：全量重建天然幂等（每次都从空状态回放）。

## 四、入口

- `pages/profile/index.wxml`：「数据维护」区新增「从交易流水重建持仓」入口，二次确认后调用云函数。
- 重建完成 toast 提示并刷新 dashboard。

## 五、非目标（v0.3 路线）

- 不接入华泰/东财等券商 OpenAPI。
- 不做基金公司 API 的份额查询对接。
- 不做自动定时同步（用户手动触发）。

## 六、验收标准

- [ ] profile 页有「重建持仓」入口
- [ ] 调用后 holdings 与 transactions 口径一致
- [ ] 清仓标的被正确标记
- [ ] 重复调用结果一致（幂等）
